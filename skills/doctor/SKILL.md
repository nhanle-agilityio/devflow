# /devflow:doctor

Arguments: $ARGUMENTS

Reports the health of the devflow setup. Read-only by default. With `--fix`, change only what the user confirms, one item at a time (AskUserQuestion). Never merge, never force push, never push to the base branch or a protected branch, never delete a protected branch or the base. GitHub operations go through the GitHub MCP server (load its tools with ToolSearch). No `Co-Authored-By` or AI attribution anywhere.

**Merged state:** never trust a `merged` field from a PR list or search result; the GitHub MCP list tools report `merged: false` for merged PRs. A PR is merged when `pull_request_read` (method `get`) returns a non-null `merged_at`, or when `git merge-base --is-ancestor <head sha> <remote>/<baseBranch>` succeeds after a fetch. Closed with neither: closed without merging. Take "merged by" and "merged at" from `pull_request_read`, not from a list.

Run all checks even when one fails. If `.claude/devflow.json` is missing, report fail for check 1, suggest `/devflow:init`, and run only checks 3, 8, 9 and 10 (none of them needs the config).

## Checks

1. **Config.** `.claude/devflow.json` parses and validates against `.claude/devflow.schema.json` (required keys, types, no unknown keys). Compare `devflowVersion` with the installed plugin version (`version` in `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json`). A lower major or minor version, or a missing value: warn, suggest `/devflow:init --upgrade`. A lower patch version only is ok: patch releases never change templates, the schema or config keys.
2. **Templates.** Compare byte for byte every installed template file with the plugin's (the same list and comparison as `/devflow:init --upgrade`: the three workflows, `.github/scripts/devflow-merge-gate.cjs`, `.claude/devflow.schema.json`; a reusable-mode caller is compared with `templates/github/callers/` and its pinned tag with the plugin version). List the drifted ones. Report only; the fix is `/devflow:init --upgrade`.
3. **GitHub access.** The GitHub MCP server is reachable (get the authenticated user). Report the tool prefix of the server that answered (for example `mcp__github__*`). It is `warn` when `.claude/settings.json` allows a GitHub MCP prefix other than that one and does not allow that one (background sessions would be refused); `ok` when both are allowed; when no GitHub MCP prefix is allowed at all, leave it to check 8. Check whether `gh` is installed (`gh --version`). Missing `gh` is only a warn; say that when `gh` is missing and the MCP connection drops, runs stop.
4. **Worktrees.** `git worktree list`, restricted to `worktree.dir`. For each: clean or dirty, branch, pushed or not (`git status --porcelain`, branch against `<remote>/<branch>`). `--fix`: remove (`git worktree remove`, no `--force`) the clean ones whose branch is pushed or merged; never a dirty one.
5. **Branches.** Local and remote branches matching `branchPattern` whose PR is merged (merged per the Merged state rule) or closed. `--fix`: delete the local ones with `git branch -d`. When that refuses (a merged PR whose merge commit git does not see as an ancestor), print `git branch -D <branch>` for the user to run: the guard hook blocks `-D` for Claude. Remote ones only after an explicit yes per branch (`git push <remote> --delete <branch>`); never the base, never `protectedBranches`, never a branch with an open PR.
6. **Claims.** Open issues labelled `labels.inProgress` with no running session (`claude agents`; none is working on it) and no open PR, older than 2 hours since the claim: stale. Also `<!-- devflow-claim ... -->` comments on issues that are not in progress: stale. Report both. `--fix`: after a yes per item, delete the stale claim comment and, for an in-progress issue, swap `labels.inProgress` for `labels.ready`, and remove the issue's assignee only when it is the authenticated user (other assignees are kept).
7. **Open PRs.** Open PRs labelled `labels.devflow` that are behind their base, conflicting, or have red checks. Report them and point at `/devflow:sync #<pr>`. Never fix them here.
8. **Allow-list.** `.claude/settings.json` has the `permissions` allow rules background sessions need: the output of `node "${CLAUDE_PLUGIN_ROOT}/bin/devflow-setup" allow < .claude/devflow.json` (git, the remote, checks, verify, worktree setup, MCP tools; use the GitHub MCP prefix the project already allows). List what is missing (warn), and the `manual` commands the user must allow by hand (no safe specific prefix). A bare interpreter, shell or runner rule already in the list (`Bash(python3:*)`, `Bash(node:*)`, `Bash(bash:*)`, `Bash(npx:*)`) is a warn: it allows any code; suggest the specific rule instead. `--fix` after a yes: merge them in; never add a deny rule or a rule that allows merging a PR or pushing to a protected branch.
9. **Owned by the plugin now.** Project files and rules that duplicate what the plugin does: `.claude/hooks/block_git_add_all.py` and its test, the `settings.json` hook that runs it and a `hook-test` style entry in `checks`; deny rules the guard enforces (force push, `gh pr merge`, pushes to protected branches, destructive git, `git add -A`); a maintenance `.claude/loop.md`; a project `.claude/agents/code-reviewer.md`. Build the list with `node "${CLAUDE_PLUGIN_ROOT}/bin/devflow-setup" leftovers` given `{"settings": <.claude/settings.json>, "config": <.claude/devflow.json>, "files": <git ls-files .claude>}`. Report each as `warn` with why it is removable and what replaces it. Never delete, edit or unregister any of them, also not with `--fix`: the user removes them (a project agent may hold project rules worth moving into CLAUDE.md first; say so).
10. **Guard.** The guard hook must work on this machine, or nothing blocks merges, force pushes or `git add -A`. Run `printf '%s' '{"tool_name":"mcp__x__merge_pull_request","tool_input":{}}' | python3 "${CLAUDE_PLUGIN_ROOT}/hooks/guard.py"; echo $?` and expect exit status `2`. Anything else (python3 missing, a crash, exit 0) is `fail`: the guard is not protecting this machine. Fix: install Python 3.9+ and make sure `python3` is on the PATH of non-interactive shells (the hook runs without your shell profile); if it still crashes, report the guard's stderr to the plugin maintainers. Read-only; `--fix` has nothing to change here.

## Report

Print a table: check, status (`ok` / `warn` / `fail`), what to do. `fail` is something that stops the workflows (config invalid, MCP unreachable); `warn` is drift or leftovers. With `--fix`, add a line per fix applied or declined. End with the one command to run next, if any.
